# StarForge

Telegram-бот із колесами удачі, спільним банком, іграми з кубиком, сезонним пасом,
чат-активностями й WebApp-застосунком (`wheel.html`).

## Запуск

```bash
npm install
cp .env.example .env   # заповни BOT_TOKEN, ADMIN_CHAT_ID, WEBAPP_URL, DATA_DIR
npm start
```

Потрібен Node.js 18.17 або новіший.

### Railway

1. Підключи **Volume** і задай `DATA_DIR` на його шлях (наприклад `/data`).
   Без цього база лежить у папці проєкту й **стирається при кожному деплої**.
2. `WEBAPP_URL` = `https://<твій-домен>/wheel.html`. Бот сам ставить кнопку меню
   «🎰 Колеса» і список команд.
3. Перевірка живучості: `GET /health`.

## Структура

| Файл | Що всередині |
|---|---|
| `server.js` | бот (Telegraf) + HTTP API застосунку (Express) |
| `wheel.html` | WebApp: колеса, банк, гаманець, профіль |
| `public/img/` | картинки призів (віддаються з кешем на 7 днів) |
| `chat.js` | активності в групі: дропи, вікторини, дуелі, ігри, рівні |
| `bank.js` | спільний банк із перевірюваним (provably fair) розіграшем |
| `pass.js` | сезонний пас: рівні, XP, нагороди |
| `league.js` | ліга тижня (зараз вимкнена прапорцем `LEAGUE_ENABLED`) |
| `db.js` | JSON-база з відкладеним атомарним записом і резервною копією |
| `config.js`, `i18n.js`, `assets.js` | налаштування, тексти трьома мовами, картинки для бота |

## Тести

```bash
npm test
```

Інтеграційні тести запускають справжній `server.js` проти фейкового Telegram Bot API
(`test/helpers.js`) і перевіряють спіни, вивід, ризик, оплату, техроботи й підпис initData.

## Що змінилось у версії 2.0

### Критичні баги
- **Щоденне колесо зависало приблизно на кожному третьому спіні.** Коли випадали білети,
  сервер падав з `Assignment to constant variable` уже *після* списання спіну:
  людина втрачала спін, застосунок не отримував відповіді, статистика й гарантії не
  оновлювались. Спін переписано: спершу всі перевірки, потім одне атомарне списання.
- **Вікно результату «зависало» на +8⭐ і +12⭐.** Для них не було опису, показ падав,
  а кнопка «Продовжити» лишалась схованою.
- Виграш у кубиках нараховувався через 4 с у таймері — перезапуск сервера його з'їдав.
  Тепер зараховується одразу; якщо кубик не надіслався, ставка повертається.
- Вікно «Секретне завдання» вискакувало знову через 8 с після закриття (часто посеред спіну).

### Економічні дірки
- **Тапалка**: API давав до ~5700⭐ на добу прямими запитами (в інтерфейсі її не було). Вимкнено.
- **Ризик ×2**: можна було витратити виграш, а потім «ризикнути» ним безкоштовно
  (виграш додавав зірки, програш упирався в нуль). Тепер ризик — лише зірками на балансі.
- **Банк**: якщо ставили лише білети, переможець отримував усю *вагу* як зірки
  (1🎫 → 5⭐). `/bank_cancel` так само повертав білети зірками. Виправлено;
  `/bank_start` більше не затирає відкритий банк зі ставками.
- **Реферали**: кожен друг давав 2 білети замість 1; давні гравці могли «стати
  рефералом» друга, відкривши його посилання. Тепер реферал — лише новий гравець.
- **Оплата**: зараховується реально сплачена сума (`total_amount`, валюта XTR),
  а не число з payload; `pre_checkout` перевіряє рахунок; дубль платежу ігнорується.
- **Преміум-колесо вимкнене, але спіни на нього продавались** за реальні зірки.
  Продаж закрито; оплата такого рахунку зараховується на баланс.
- Відхилення заявки на **вивід чи покупку в магазині** не повертало зірки. Тепер
  повертає (і `/reject`, і `/cancel_inactive`, і `/reset_requests` — однаково).
  `/reset_requests` раніше повертав за магазин ціну +10%, якої ніхто не платив.

### Безпека
- **XSS у застосунку**: ім'я гравця на кшталт `<img onerror=…>` виконувалось у всіх,
  хто бачив стрічку виграшів або сектори банку. Усі імена екрануються.
- Підпис `initData` перевіряється за сталий час і має термін дії (7 днів).
- Імена в HTML-повідомленнях бота й чату екрануються (раніше ламали оголошення).
- Техроботи `full` блокують дії й на сервері, а не лише екраном у браузері.
- Ліміти: тіло запиту 64 КБ (8 МБ лише для скріна-доказу), ~600 запитів/хв з адреси,
  скрін-доказ — раз на 10 хв, пароль-челендж — раз на 3 с.
- Пароль `/unlock_event` береться зі змінної `ADVANCED_UNLOCK_PASSWORD`.

### Надійність і швидкість
- Будь-який виклик Telegram API на 429 чекає `retry_after` і повторює — розсилки
  більше не губляться.
- Старт бота з повторами (у т.ч. на 409 після деплою) і коректна зупинка з дописом бази.
- `wheel.html` важив 645 КБ через вбудовані base64-картинки й завантажувався наново
  при кожному відкритті. Тепер 268 КБ (66 КБ у gzip), картинки — окремими файлами з кешем.
- База пишеться без відступів (удвічі менший файл і швидший запис).
- Журнал колеса більше не забивається подіями «відкрив» — у ньому лишаються спіни.

### Зручність
- У головному меню — кнопка «🎰 Відкрити колеса», кнопка меню біля поля вводу, список команд.
- Бонусні спіни (питання дня, завдання, `/winback`) більше **не ламають серію днів** —
  вони йдуть окремим лічильником, а кнопка колеса показує «🎁 Бонусний спін (N)».
- Подаровані спіни «За зірки» працюють навіть без балансу.
- Колесо «За білети» відкривають білети, а не кількість друзів.
- Вивід — будь-яка сума від 15⭐ (застосунок раніше пропускав лише «номінали»),
  з точною причиною відмови.
- Питання дня нарешті показується в застосунку; на головній — бонусні спіни, білети, питання.
- Історія показує білетні виграші як «+3 🎫», а не «+0⭐».

### Нове для адміна
- `/spin_notify on|off` — сповіщення про кожен спін (призи приходять завжди).
- `/wheel_abuse_punish так` — масове покарання тепер лише з підтвердженням і не
  чіпає чесних гравців із бонусними спінами.

### Відомі обмеження
- `pass.js` не було серед файлів — його відтворено за тим, як його використовує
  `server.js`. Ціни й нагороди пасу (150⭐ / 100 XTR, 30 рівнів по 100 XP) — у
  верхній частині `pass.js`, зміни під себе.
- `jackpot.jpg` для джекпоту в чаті не було — бот оголошує джекпот текстом.
